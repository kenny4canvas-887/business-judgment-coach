# 阶段追问提示（教练内部使用）

参照业务增长工具箱 `advise-business-stage/references/stage-model.md`。下表代码只供教练内部选择追问，绝不写进对用户的提问、回看卡或HTML。对外如确有必要，只说“正在找真实需求”“正在确认客户能否得到价值”“正在判断能否稳定复制”“正在决定资源投向”等直白阶段。只选眼前最早未证实、会改变行动的一项；公司成熟度不能代替当前项目证据。以下是练习线索，不是正式阶段诊断，也不是逐项问卷。用户已经给出答案时跳过。

| 眼前决策 | 最该抓的张力 | 一个可改写的追问 |
| --- | --- | --- |
| K0：要不要进入一个方向 | 市场看起来大，但是否有属于自己的进入位置 | “你最想服务的那群人，现在为了这个问题已经放弃了什么，或花了什么代价？” |
| K1：先验证哪类客户 | 口头兴趣很多，但谁有真实行动 | “如果这周只能跟一类客户，你选谁？他已经做过什么，能让你相信这不是客气话？” |
| K2：先交付什么价值 | 功能想做很多，但哪一步让客户真正得到结果 | “如果只能保留一个环节，客户完成哪件事后才会说这次投入值得？” |
| S5：是否复制放大 | 一个点做成了，但离开关键人还能否稳定重复 | “把这个做法交给另一组人，最先可能在哪一步失灵？已有哪次复制证明它能撑住？” |
| S6：成熟业务资源投向 | 收入大，不等于利润、现金和服务占用都划算 | “继续给这个客户加资源，会从谁那里拿走什么？算上回款和服务后，你还会这样选吗？” |

若核心在增长断点、交付资源瓶颈或转型，可参考原工具箱 K3、K4、S7 的同一原则：只问当前决定需要的一个关键变量，不硬塞到上表。相邻问题交错时，向用户说出暂时判断及可能改判的证据，允许纠正；不同时给多个阶段标签。问题的力度来自取舍及反证，语气保持平等，不用“你为什么还不知道”或连串审问。客户经营案例仍检查存量服务义务与关系风险。
