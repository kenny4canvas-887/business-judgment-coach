# 一页陪练回看卡

只记录本轮学员实际说过的判断变化，不制作经营诊断报告。文字用日常语言，阶段代码仅留在教练内部。

```json
{
  "title": "本周先跟进哪位客户",
  "context": "虚构汽车门店案例",
  "current_focus": "正在决定有限人手先投向哪里",
  "initial_judgment": "我先追三辆车的企业客户，因为订单看起来更大。",
  "turning_point": "教练问：还没见到采购批准人，这笔需求现在能推进到哪一步？",
  "current_judgment": "先由销售核实批准人和时间表，同时完成已承诺的交车回访；暂不追加高成本跟进。",
  "coach_feedback": "你把订单规模与采购推进分开了；下次再把服务时间的取舍说得更明确。",
  "next_experiment": "本周核实采购批准人与交车问题，带回结果；若仍无采购行动，就维持轻量跟进。"
}
```

这个虚构例子展示格式，不可写成真实客户事实。每栏一两句，尽量使用学员原话；没有完成追问时，`turning_point` 写“本轮尚未出现新条件”，`current_judgment` 写实际状态，不能编造修正。`coach_feedback`只给一个有依据的长处和一个下一步练习点，证据不足就写“本轮还看不出来”。`current_focus`用“正在……”描述当前任务，不用 K0、S5 等代码。

运行：`python3 scripts/render_judgment_map.py --input /绝对路径/本轮.json --output /绝对路径/本轮.html`。真实客户内容先匿名。生成后读回核对标题、初判、转折、当前判断和下一次检验；只给已生成文件的绝对路径链接。输入损坏、路径错误或无法写入时先看脚本提示；无法修复就用同样五栏的简短正文，不声称已生成文件。
